## P0 — Bug 修复（必须）

### P0-1 可用端口卡片（gap card）不显示

**现象**：用户设置监控区间后，已用端口之间的可用端口不显示为卡片。

**根因（两处）**：

1. **后端 — head gap 缺失**（`app/services/port_monitor.py:534-624`）
   `_merge_unknown_and_gaps()` 只在「当前卡 → 下一卡」之间和「末卡 → end_port」之间插入 gap。
   若区间 1-100 只有 80 被占用，gap 1-79（head gap）永远不会生成。

2. **前端 — gap 模板缺失**（`frontend/src/components/PortsView.vue:310-423`）
   模板只渲染 `card.type === 'used'` 和 `card.type === 'unknown_range'`，
   **没有 `card.type === 'gap'` 的 `<template>` 块**，即使后端返回 gap 卡片也不渲染。

**修复方案**：

| 文件 | 改动 |
|------|------|
| `app/services/port_monitor.py` | 在 `_merge_unknown_and_gaps()` 循环前，检查 `port_data_list[0].port > start_port`，若成立则插入 head gap 卡片 |
| `frontend/src/components/PortsView.vue` | 在 `port-grid` 内新增 `card.type === 'gap'` 模板块，展示 `start_port — end_port` + `available_count` 个可用端口 |
| `frontend/src/style.css` | 新增 `.gap-card` 样式（虚线边框、浅色背景、居中文字） |
| `frontend/src/locales/zh.json` / `en.json` | 新增 `gap.available` 等 i18n key |

**验收**：区间 1-100，仅 80 被占用 → 显示 gap 1-79（79 个可用）+ 端口 80 + gap 81-100（20 个可用）。

### P0-2 安全开关：未设密码也能开启登录

**现象**：`SettingsView.vue:34-37` 的 `handleToggleAuth()` 直接调用 `auth.doToggle()`，不检查 `has_password`。
用户未设密码就开启登录 → 任何人都能访问（无密码可输）。

**根因**：`auth.py:114-123` 的 `toggle` 端点也不校验密码是否存在。

**修复方案**：

| 文件 | 改动 |
|------|------|
| `frontend/src/components/SettingsView.vue` | `handleToggleAuth()` 开启前检查 `auth.state.value.has_password`，若为 false 则 toast 提示「请先设置密码」并聚焦密码输入框 |
| `app/routers/auth.py` | `toggle` 端点：`enabled=True` 且 `has_password()=False` 时返回 400 + 提示 |

**验收**：未设密码时点击「开启」→ 提示先设密码；设密码后可正常开启。

### P0-3 刷新间隔设置后不实时生效

**现象**：在设置页改刷新间隔后，左下角状态栏仍显示旧值；需重新登录才更新。

**根因**：
- `App.vue:67` 的 `refreshInterval` 是局部 `ref`，仅在 `onMounted` 时从 `getPrefs()` 读取一次。
- `SettingsView.vue:130-133` 的 `onRefreshIntervalChange()` 只调 `patchPrefs()` 写后端，不通知 App.vue。
- `App.vue:159-169` 的 `applyStatsTimer()` 依赖 `refreshInterval.value`，但值从未被更新。

**修复方案**：

| 文件 | 改动 |
|------|------|
| `frontend/src/store/prefs.ts`（新建） | 创建共享 reactive store：`refreshInterval: Ref<number>`，提供 `setRefreshInterval(v)` 方法，内部调 `patchPrefs` + 更新 ref |
| `frontend/src/App.vue` | 从 `usePrefs()` 读取 `refreshInterval`，`watch` 变化时调 `applyStatsTimer()` |
| `frontend/src/components/SettingsView.vue` | 改用 `usePrefs().setRefreshInterval()` 替代本地 `refreshInterval` ref |

**验收**：设置页选 15 秒 → 状态栏立即显示「自动刷新 15s」，定时器立即生效。

### P1-5 首次启动密码提示（新增）

**用户要求**：首次打开（尚未设置密码）时提示用户设置密码，可选「立即设置」或「暂不设置，稍后设置」。

**已确认交互**：
- 弹窗内直接填（新密码 + 确认密码），无需跳转
- 只提示一次（选「暂不设置」后不再弹，但状态栏保留「未设密码」入口可随时再设）
- 弹窗内加「同时开启登录保护」勾选项（默认勾选）

**触发条件**：`!auth.state.value.has_password` 且 localStorage `portview.pwPromptDismissed` 未置位。

**改动**：

| 文件 | 改动 |
|------|------|
| `frontend/src/components/PasswordPrompt.vue`（新建） | 首次启动密码提示弹窗：<br>1. 标题「设置访问密码」+ 说明<br>2. 新密码 + 确认密码输入框<br>3. 「同时开启登录保护」复选框（默认勾选）<br>4. 「保存」按钮：校验（≥4 位、两次一致）→ `doSetPassword(pw)` → 若勾选则 `doToggle(true)` + `doLogin(pw)`（重新建立会话，避免被登出）→ `refresh()`<br>5. 「暂不设置」按钮：置 `portview.pwPromptDismissed=1`，关闭 |
| `frontend/src/App.vue` | 1. `refreshAuth()` 后判断 `!has_password && !dismissed` → 显示 `PasswordPrompt`<br>2. 状态栏新增「未设密码」chip（`!has_password` 时显示），点击重新打开弹窗（满足「稍后设置」） |
| `frontend/src/store/auth.ts` | 复用现有 `doSetPassword` / `doToggle` / `doLogin` / `refresh`，无需新增 |
| `frontend/src/locales/zh.json` / `en.json` | 新增 `pwPrompt.title`、`pwPrompt.desc`、`pwPrompt.enableAuth`、`pwPrompt.skip`、`pwPrompt.statusHint` 等 key |

**验收**：
1. 全新部署（无密码）首次打开 → 弹出密码提示弹窗
2. 填密码 + 勾选「开启登录保护」→ 保存 → 密码生效、登录保护开启、当前会话保持登录
3. 点「暂不设置」→ 弹窗关闭，状态栏出现「未设密码」入口
4. 再次启动不再弹窗；点状态栏入口可重新打开设置
